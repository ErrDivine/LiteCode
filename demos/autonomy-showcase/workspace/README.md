# Marvis Autonomy Showcase Workspace

This is the disposable project used by the Marvis demo driver. The driver starts from a passing baseline, introduces one focused trap at a time, runs the matching VSCode task, then waits for Marvis to wake up through status debounce or heartbeat.

The files are intentionally small, but the traps cover different kinds of agentic work: code repair, refactor fallout, test-driven business logic, frontend accessibility readiness, and documentation completion. This keeps the Marvis panel and active editor readable during a screen recording while still showing varied routing behavior.
